## Setup

CLI tests use an isolated test DB (`/tmp/pagerunner_integration_test.db`) and a
per-test daemon started via `PAGERUNNER_DB_PATH`. Session-based tests route through
the test daemon so session state persists across separate `pagerunner` CLI invocations.

Non-Chrome tests run with `cargo test --test cli_tools_integration`.
Chrome tests run with `cargo test --test cli_tools_integration -- --ignored`.

## Notable Findings

### ⚠️ `about:blank` blocked via CLI
The security policy's `check_navigate` applies to CLI calls just as it does to MCP.
`about:blank` is rejected with "Blocked scheme: about". This is correct behavior —
the same security guarantees apply in CLI and MCP modes.
CLI tests updated to use `https://example.com` instead.

### ✅ `open_session` now returns JSON
Previous plain-text response `"Session opened: <id> (stealth: false)"` changed to
`{"session_id": "...", "stealth": false}` so scripts can parse session IDs.

### ✅ DB isolation via `PAGERUNNER_DB_PATH`
CLI tests use `/tmp/pagerunner_integration_test.db` so they never conflict with a
running `pagerunner mcp` process. Session-based tests additionally route through a
per-test daemon.

### ✅ Daemon supports `PAGERUNNER_DB_PATH`
Daemon now reads `PAGERUNNER_DB_PATH` env var, enabling test isolation.
