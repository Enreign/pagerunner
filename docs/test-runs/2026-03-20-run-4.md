## Notable Findings

### ✅ Token consistency (AN4)
Same email in two separate calls (evaluate and get_content) → same token `[EMAIL:0e9899]`. Session vault correctly deduplicates.

### ✅ De-tokenization verification (AN5/AN6)
Can't directly read DOM value back because evaluate output is itself anonymized. Used `value.length` to verify: DOM had 16 chars (`billing@acme.com`) not 14 (the token string `[EMAIL:0e9899]`). `type_text` response showed "Typed 16 chars" directly.

### ✅ All 6 entity types in one call (AN17)
Single page content containing SSN, CREDIT_CARD, IBAN, and IP all tokenized in a single `evaluate` call:
```
<p>SSN [SSN:92d869], card [CREDIT_CARD:e516d4], IBAN [IBAN:b4092f], IP [IP:71f7fe]</p>
```

### ⚠️ Pre-run schema gap
The `open_session` MCP tool schema was missing the 4 anonymization parameters. Without them, Claude Code would not pass these params to the tool even if asked. Fixed in commit `483bd89` before running tests. This was a missing step in the implementation plan.
