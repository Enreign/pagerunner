## Bug Found & Fixed

### 🐛 `fill` on `<textarea>` always failed
**Root cause:** `fill` hardcoded `HTMLInputElement.prototype` to get the native value setter.
`HTMLTextAreaElement` has its own `value` property on a different prototype — calling
`HTMLInputElement.prototype.value` setter on a textarea silently no-ops, so `return true`
was never reached, causing "Selector not found" even when the element existed.

**Fix:** `src/browser.rs` — detect element type and select the correct prototype:
```js
const proto = el instanceof HTMLTextAreaElement
    ? window.HTMLTextAreaElement.prototype
    : window.HTMLInputElement.prototype;
```

**Impact:** Any `fill` call targeting `<textarea>` was broken. Affects forms with text
areas (comments, descriptions, message boxes). Fixed in this run.

### 🐛 NER inference returned no spans (`add_special_tokens=false`)
**Root cause:** `NerSession::detect()` called `tokenizer.encode(text, false)` — the `false`
flag disables `[CLS]`/`[SEP]` special tokens. BERT (dslim/bert-base-NER) was trained with
these tokens at positions 0 and N+1; without them the model sees out-of-distribution input
and predicts "O" for every token.

**Fix:** `src/anonymizer/ner.rs` — change `false` → `true`:
```rust
let encoding = self.tokenizer.encode(text, true)?;
```
The existing `special_tok_mask` loop already skips `[CLS]`/`[SEP]` during span building, so
no further changes were needed.

**Impact:** All NER entity detection was silently broken (zero spans returned). Fixed in this
run. `test_ner_detects_person_and_org` and `test_ner_spans_are_valid_byte_offsets` now pass.

## Notable Findings

### ✅ `allowed_tools` also blocks `close_session`
A session opened with `allowed_tools:["navigate","get_content"]` cannot call `close_session`
on itself — the tool is not in the allowed list. The session persists until daemon restart.
**Recommendation:** Consider whether `close_session` and `list_sessions` should be implicitly
always-allowed regardless of `allowed_tools`, or document this as intentional in the README.

### ✅ Beta profile Chrome crashes (pipe EOF)
The `beta` temp profile's Chrome process died with "Pipe read error: early eof" on multiple
attempts. Alpha and gamma were stable. Likely a stale/corrupted Chrome profile state.
**No action needed** — temp profiles are ephemeral; restarting Chrome or wiping the profile
dir resolves it.
